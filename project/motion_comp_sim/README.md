# Motion-Compensation Simulation (Phase 1, rotation-only)

Summer 2026 ELEC 497 simulation work, kept separate from the capstone Qt app
(`../Ultrasonic-Beamforming-real-time-cpp`), which it references read-only for
the real beamforming algorithm and mic geometry.

Four steps, run in order (base MATLAB or Octave, no toolboxes):

1. `step1_generate_trajectory.m` — ground-truth "shaky hand" yaw (±10° at 2 Hz, 100 Hz, 10 s) → `trajectory.mat`. DONE.
2. `step2_corrupt_to_sensor.m` — corrupt the angle stream with jitter (0.3° RMS), random-walk drift (0.05°/√s), 20 ms latency, quantization → `sensor_readings.mat`. Placeholder values until the BNO085 is bench-measured. DONE. Key finding: the 20 ms latency dominates (1.77° of the 1.80° RMS total error; error trace is a clean 2 Hz sinusoid).
3. `step3_generate_frames.m` — synthetic beamformed frames of a fixed world source (az 0°, 8 kHz tone) seen from the rotating array → `frames_step3.mat` (937 frames, 93.75 fps, 101×101 direction-cosine grid) + `step3_slosh.mp4`. DONE. Renders each frame's power map analytically with the real 102-mic geometry (`../Ultrasonic-Beamforming-real-time-cpp/microphoneLocations.csv`) and the same delay-and-sum + integer-sample rounding as `model/BeamformerWorker.cpp` — true PSF, sidelobes included. Real-system facts mirrored: fs 48 kHz, 512 samples/frame → 93.75 fps default (not commensurate with the 100 Hz sensor rate — step 4 must interpolate). Blob position extracted per frame (peak + parabolic sub-pixel, mirroring Gazor's sparse-grid-plus-offsets format) tracks the expected az₀ − yaw(t) to 0.35° RMS — that's the imaging floor, well below the 1.79° sensor error, so step-4 scoring can resolve improvement.
4. `step4_compensate_and_score.m` — counter-rotates each frame into world coordinates (proper spherical rotation of the direction-cosine image, sensor readings interpolated from 100 Hz to the 93.75 fps frame times) and scores four conditions against truth → `results_step4.mat` + `step4_before_after.mp4`. DONE. Results (RMS world-frame position error / peak of 10 s averaged image): uncompensated 7.09° / 0.31, sensor-compensated 1.82° / 0.71, sensor + 20 ms latency compensation 0.47° / 0.89, truth-compensated 0.41° / 0.89. Confirms end-to-end that latency dominates: compensating the known 20 ms lag recovers nearly all of the ideal bound. Known artifact: occasional ~1.7° single-frame spikes in the (c)/(d) error traces from the sub-pixel peak extractor on resampled images — cosmetic, worth one honest sentence in the report.

All `.mat` files and `fig_*.png` figures were generated by running the `.m`
scripts in MATLAB R2025b (2026-07-17). MATLAB-confirmed numbers: total error
1.79° RMS, latency alone 1.77° RMS, drift at end of run -0.07°.
